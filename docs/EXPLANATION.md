# Как работает мини-CRM

Система помогает руководителю распределять задачи по стройкам и проверять результат работы. На каждом объекте есть название, адрес и список задач. В задаче указаны описание работ, исполнитель, автор и текущее состояние.

Руководитель видит все объекты и задачи, может создавать и редактировать их, назначать исполнителя. Исполнитель видит только свои задачи и стройки, где ему есть что делать. Даже на общем объекте чужие задачи остаются скрыты.

Исполнитель берёт новую задачу в работу, а после выполнения отправляет на проверку. Руководитель принимает результат или возвращает задачу на доработку. При возврате обязательно указать причину. После доработки исполнитель снова отправляет результат на проверку. Перескакивать через этапы нельзя.

В карточке сохраняется история: кто и когда изменил состояние задачи, каким оно было раньше, каким стало и какой комментарий оставил участник. Участники не могут исправлять или удалять отдельные записи истории.

Ограничения действуют там, где хранятся данные, а не только на экране. Если исполнитель попытается обратиться к данным напрямую, система всё равно не покажет чужие задачи, не позволит назначить себе другую задачу, изменить свою роль или самостоятельно принять результат. Смена состояния и запись в историю выполняются вместе: одна операция не сохранится без другой.

Аккаунты создаёт администратор; свободной регистрации нет после отключения соответствующей настройки в Supabase. Удалять задачи может руководитель; при этом задача удаляется вместе со своей историей. Объект с существующими задачами удалить нельзя.
