# Проверка после подключения Supabase

## Через приложение

1. Войти постановщиком: видны 3 демонстрационных объекта и все 6 задач. Создать объект, изменить название и адрес.
2. Создать задачу, назначить исполнителя, открыть карточку, изменить описание, объект и назначение. Проверить автора, дату и начальную запись истории.
3. Войти первым исполнителем: видны только его задачи и 2 объекта. На общих объектах не видны задачи второго исполнителя. Проверить то же прямым открытием URL чужой задачи и третьего объекта.
4. Провести свою новую задачу по циклу: «Новая → В работе → На проверке». Кнопки соответствуют роли и текущему статусу.
5. Постановщиком попробовать вернуть задачу без комментария, затем с причиной. Исполнителем пройти «На доработке → В работе → На проверке»; постановщиком принять.
6. Сверить историю, комментарии и имена пользователей. У принятой задачи нет кнопок следующего статуса.
7. Назначить задачу другому исполнителю: предыдущий теряет доступ и к её истории. Если на объекте нет других его задач, объект тоже исчезает.
8. Объект с активными задачами архивировать нельзя. Архивировать тестовую задачу с подтверждением: она исчезает из активного списка, в архиве постановщика сохраняются данные и вся история. Исполнитель больше не видит задачу и историю даже по прямой ссылке. Архивную задачу нельзя редактировать или менять её статус. После архивирования всех задач архивировать объект; открыть его через архив объектов и сверить историю задач.
9. Обновить страницу карточки: сессия сохраняется, маршрут открывается. Выйти: защищённые маршруты перенаправляют на вход.
10. Проверить вход по неверному паролю, отказ сети, пустые списки, узкий экран.

## В обход интерфейса

Использовать **публичный ключ и access token обычного вошедшего пользователя**. SQL Editor и `service_role` обходят RLS и не подходят для проверки пользовательских прав.

В отдельном Node.js REPL (`node` из папки проекта) можно создать клиент из уже установленных зависимостей:

```js
const { createClient } = await import('@supabase/supabase-js')
const client = createClient('YOUR_PROJECT_URL', 'YOUR_PUBLIC_KEY', {
  auth: { persistSession: false, autoRefreshToken: false, detectSessionInUrl: false }
})
await client.auth.signInWithPassword({ email: 'executor1@example.com', password: 'YOUR_PASSWORD' })
```

Используйте собственные ID из демонстрационной базы. Не копируйте токены и пароли в репозиторий или публичные отчёты.

Проверить запросы:

```js
// Все возвращённые задачи принадлежат вошедшему исполнителю.
await client.from('tasks').select('*')

// Чужие ID не раскрывают данные: пустой массив.
await client.from('tasks').select('*').eq('id', 'OTHER_EXECUTOR_TASK_ID')
await client.from('task_status_history').select('*').eq('task_id', 'OTHER_EXECUTOR_TASK_ID')

// Исполнитель не может править обычные поля: нет изменённых строк.
await client.from('tasks').update({ title: 'Подмена' }).eq('id', 'OWN_TASK_ID').select()

// Прямое изменение статуса запрещено, включая постановщика.
await client.from('tasks').update({ status: 'accepted' }).eq('id', 'OWN_TASK_ID')

// Пропуск этапов и принятие собственной задачи исполнителем запрещены.
await client.rpc('change_task_status', { p_task_id: 'NEW_OWN_TASK_ID', p_next_status: 'accepted' })

// Физическое удаление задач и объектов запрещено обеим ролям.
await client.from('tasks').delete().eq('id', 'OWN_TASK_ID')
await client.from('objects').delete().eq('id', 'OBJECT_ID')

// Исполнитель не может архивировать задачи и объекты.
await client.rpc('archive_task', { p_task_id: 'OWN_TASK_ID' })
await client.rpc('archive_object', { p_object_id: 'OBJECT_ID' })

// Роли и история защищены от записи.
await client.from('profiles').update({ role: 'manager' }).eq('id', 'OWN_PROFILE_ID')
await client.from('task_status_history').delete().eq('task_id', 'OWN_TASK_ID')
await client.from('task_status_history').update({ comment: 'Подмена' }).eq('task_id', 'OWN_TASK_ID')
await client.from('task_status_history').insert({ task_id: 'OWN_TASK_ID', actor_id: 'OWN_PROFILE_ID', to_status: 'accepted' })
```

Повторить проверки изменения статуса и истории под постановщиком. Через RPC он может принимать и возвращать только задачи на проверке; возврат с `p_comment: '   '` запрещён.

Под постановщиком на отдельном тестовом объекте сохранить историю тестовой задачи, вызвать `archive_task` и убедиться, что история осталась без изменений, а `archived_at` установлен. Прямой `UPDATE archived_at` запрещён; изменение обычных полей архивной задачи не затрагивает строк, смена статуса через RPC отклоняется. После `archive_object` данные и история по-прежнему читаются постановщиком; создание задачи на архивном объекте и перенос туда активной задачи отклоняются. Для архивирования создавать отдельные тестовые записи: они остаются в архиве.

Отдельным клиентом без входа убедиться, что таблицы и RPC недоступны. Попытка `client.auth.signUp()` с новым адресом должна отклоняться **самим Supabase Auth**. Проверять на одноразовом тестовом адресе; если регистрация удалась, отключить настройку регистрации и удалить созданный тестовый аккаунт вручную.
