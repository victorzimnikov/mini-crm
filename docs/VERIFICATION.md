# Проверка опубликованной версии

Дата: 4 ноября 2026 года.

Этот отчёт относится к развёртыванию **до** миграции `202611040002_preserve_task_history.sql`. Архивирование проверено локальными тестами; в облаке новая миграция и новая сборка в рамках этого изменения не применялись. После обновления нужно повторить сценарии из `docs/ACCEPTANCE.md`.

Приложение: https://mini-crm-drab-mu.vercel.app

## Результат

Проверки реального Supabase API от имени одного постановщика и двух исполнителей прошли: **71 проверка, код завершения 0**. Использованы публичный ключ и обычные пользовательские сессии, без административного ключа. Отдельно проверены запреты для анонимного пользователя и интерфейс в браузере.

## Хостинг и вход

- Прямое открытие `/objects` возвращает приложение с HTTP 200 и переводит на вход без сессии.
- Параметры Supabase в опубликованной сборке совпадают с локальными параметрами подключения.
- Вход постановщика и первого исполнителя проверен в браузере; все три аккаунта прошли проверку входа и роли через Auth/API.
- Повторное открытие вложенного маршрута сохраняет сессию.
- Открытая регистрация отключена: Auth settings возвращает `disable_signup: true`.
- В консоли страницы входа ошибок и предупреждений не обнаружено.

## Доступ к данным

- Все четыре таблицы и функция смены статуса недоступны без входа: HTTP 401, код PostgreSQL `42501`.
- Постановщик видит все данные. Исполнители видят только назначенные им задачи и объекты, где такие задачи есть.
- На общем объекте исполнитель не получает чужие задачи. Запрос чужой задачи и её истории по известному ID возвращает пустой результат.
- Исполнитель не может редактировать обычные поля задачи или изменить собственную роль.
- Прямое изменение статуса запрещено обеим ролям. Постановщик не может подменить автора задачи.
- После переназначения задачи прежний исполнитель теряет доступ к задаче, истории и объекту без других своих задач; новый исполнитель получает доступ.

## Статусы и история

- Проверен цикл `new → in_progress → review → revision → in_progress → review → accepted`.
- Отклонены пропуск стадий, действие другого исполнителя, принятие задачи исполнителем, начало работы постановщиком и повторные переходы.
- Возврат на доработку без комментария и с одними пробельными символами отклоняется базой.
- История содержит ровно создание и шесть успешных переходов; неудачные операции не добавляют записей.
- Проверены автор действия и комментарий при возврате.
- Вставка, изменение и самостоятельное удаление истории запрещены и постановщику, и исполнителю.

## Изменения данных при проверке

Созданы отдельный временный объект и две временные задачи. На них проверены создание, изменение обычных полей, цикл статусов, переназначение и запрет удаления объекта с задачами. После проверки эти записи удалены в правильном порядке. Количество объектов и задач вернулось к исходному; исходные записи не редактировались.

## Границы проверки

Это проверка текущего развёртывания и основных требований ТЗ, а не нагрузочный тест или полный аудит безопасности. Проверено отключение регистрации через публичные настройки Auth; попытка создать дополнительный аккаунт не выполнялась. Мобильный интерфейс отдельно в облачном развёртывании не проверялся.
